# User Management CRUD Module

Build a clean, beginner-friendly, production-style **User Management CRUD Module** using:

* React
* TypeScript
* React Hook Form
* Zod
* Ant Design
* Ant Design Table
* TanStack Query
* Axios
* Zustand
* Tailwind CSS

The goal is to build a realistic CRUD module while learning how to properly separate:

* Form state
* Validation
* Server/API state
* Client/UI state
* API logic
* UI components

---

# 1. Technology Responsibilities

Use each library for its appropriate responsibility.

### React Hook Form

Use React Hook Form for:

* Form state
* Field registration
* Form submission
* Resetting the form
* Managing form errors

Do not manually create separate `useState` variables for every form field.

### Zod

Use Zod for all form validation.

Integrate Zod with React Hook Form using:

```ts
zodResolver
```

### TanStack Query

Use TanStack Query for **server/API state**.

Use:

* `useQuery`
* `useMutation`
* `useQueryClient`

TanStack Query should handle:

* Fetching users
* Creating users
* Updating users
* Deleting users
* Loading states
* API errors
* Cache management
* Query invalidation

Do not store the fetched users array inside Zustand.

### Zustand

Use Zustand only for **client/UI state**.

For example:

* Current editing user
* Create/Edit mode
* Other shared UI state when appropriate

Do not duplicate TanStack Query server data inside Zustand.

### Axios

Use Axios for HTTP requests.

Keep API requests inside a dedicated API/service layer.

### Ant Design

Use Ant Design for:

* Table
* Modal
* Input
* Radio
* Checkbox
* Select
* Button
* Empty
* Loading indicators
* Notifications/messages

### Tailwind CSS

Use Tailwind CSS for application layout and custom styling.

Do not create unnecessary CSS files when Tailwind utility classes can handle the styling.

Use Tailwind for:

* Page layout
* Spacing
* Width/height
* Typography
* Flexbox/Grid
* Form layout
* Responsive design
* Button positioning
* Section styling
* Containers/cards

Ant Design should still be used for its functional UI components such as `Table`, `Modal`, `Input`, `Select`, `Radio`, `Checkbox`, and `Button`.

Use Tailwind to control the overall appearance and layout around these components.

# 7. Create User

When submitting in Create mode:

1. React Hook Form validates the form.
2. Zod performs schema validation.
3. Call the create-user TanStack Query mutation.
4. Show loading state.
5. On success:

   * Show Ant Design success notification.
   * Reset the form.
   * Return to Create mode.
   * Invalidate the users query.
6. On error:

   * Show Ant Design error notification.
   * Keep the entered form values.

Success message:

```text
User created successfully!
```

# 9. Edit User

Add an Edit button inside the Actions column.

When clicked:

1. Store the selected user in Zustand.
2. Change the form to Edit mode.
3. Populate the form using React Hook Form `reset()`.
4. Disable the password field.
5. Allow the user to update the other fields.

```text

```

```text

```

* Clear editing user
* Reset the form
* Return to Create mode

# 10. Update User

When submitting in Edit mode:

1. Validate with Zod.
2. Call update mutation.
3. Show loading state.
4. Update server data through TanStack Query.
5. Invalidate/refetch users query.
6. Show success notification.
7. Reset form.
8. Clear editing user from Zustand.
9. Return to Create mode.

Success message:

```text
User updated successfully!
```

The table must update without a page reload.

# 11. Delete User

When clicked, display an Ant Design `Modal`.

Modal text must be:

```text

```

Buttons:

```text
Cancel
Confirm
```

### Cancel

* Close modal
* Do not delete user

### Confirm

1. Call delete mutation.
2. Show loading state on Confirm button.
3. Delete user through API.
4. Invalidate/refetch users query.
5. Close modal.
6. Show success notification.

Success message:

```text
User deleted successfully!
```

If deletion fails:

```text

```

# 16. Zustand Architecture

Zustand should manage only client/UI state.

For example:

```ts
interface UserStore {
  editingUser: User | null;

  setEditingUser: (user: User | null) => void;
}
```

Potential flow:

```text
Click Edit
    ↓
Zustand stores editingUser
    ↓
UserForm detects edit mode
    ↓
React Hook Form reset()
    ↓
User edits form
```

Do not store the fetched users array in Zustand.

# 25. Important State Management Rule

Clearly separate the three types of state:

```text
React Hook Form
→ Form State

TanStack Query
→ Server/API State

Zustand
→ Client/UI State
```

Do not mix these responsibilities.

For example:

```text
users[]
```

belongs to:

```text
TanStack Query
```

while:

```text
editingUser
```

can belong to:

```text
Zustand
```

and:

```text
fullName
email
gender
skills
country
termsAccepted
```

belong to:

```text
React Hook Form
```
